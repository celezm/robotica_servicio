Práctica 1

Localized Vacuum Cleaner

Planificación de cobertura para un robot aspirador localizado en un entorno doméstico.

Práctica 1

Objetivo

El objetivo de esta práctica es, dado el mapa de una casa, planificar la ruta por la que debe pasar un robot aspirador.

Para planificar la ruta, el objetivo es ir enlazando espirales, generadas mediante el algoritmo BSA, y determinando posibles puntos de retorno hasta completar el mapa.

Desarrollo

El desarrollo de esta práctica se ha dividido en los siguientes ficheros de código:

  • main.py
  • register.py
  • map_processing.py

Registro entre el mapa y Gazebo

En primer lugar, se implementa un registro del mapa. Es decir, se obtiene la correspondencia entre las posiciones del mapa, representadas mediante píxeles, y las posiciones del mundo de Gazebo, representadas mediante coordenadas de tipo float.

Para ello, al inicio del desarrollo de la práctica, obtuve 10 puntos del mapa y busqué la correspondencia de esas posiciones en el mundo de Gazebo.

Sin embargo, durante las pruebas del código me di cuenta de que, debido a la forma en la que se habían obtenido estos puntos, el robot acumulaba bastante error y se chocaba con distintas partes de la casa, pese a aplicar operaciones de erosión y dilatación sobre la imagen.

Para tratar de solucionarlo, he ido modificando estos puntos para que sean más fieles a la posición real y he incrementado el número de puntos hasta 14, con el objetivo de minimizar el error de posición.

Procesamiento del mapa

Una vez obtenida esta correspondencia, se procesa el mapa dividiendo la imagen en celdas.

Pese a que el enunciado determina que el tamaño estimado del robot es de 35x35 píxeles, he utilizado un tamaño de celda menor, de 22x22 píxeles, para favorecer la correspondencia con el tamaño de la imagen, puesto que con el tamaño anterior las celdas no encajaban correctamente con el mapa.

Para el procesamiento del mapa se ha seguido el siguiente pipeline:

  1. Erosión de la imagen. Tras distintas pruebas, cambiando el tipo de kernel y el número de iteraciones, se ha aplicado una erosión con un kernel en forma de elipse y un tamaño de 30x30 píxeles. Se utiliza una sola iteración, ya que este kernel produce una erosión suficientemente agresiva.
  2. División de la imagen en celdas. La imagen se divide utilizando celdas de tamaño 22x22 píxeles.
  3. Clasificación de las celdas. Las celdas se clasifican en:
    • OCCUPIED: celdas ocupadas o situadas fuera de la zona navegable del mapa.
    • FREE: celdas por las que puede desplazarse el robot.

Este procesamiento se ha implementado mediante distintas funciones en el fichero map_processing.py.

Planificación de la ruta

Una vez obtenido el mapa procesado, comienza la planificación de la ruta.

Para ello se sigue el siguiente pipeline:

  1. Se obtiene la posición inicial del robot y se determina una orientación inicial para comenzar la ruta.
  2. Se genera la primera espiral utilizando el algoritmo BSA. El funcionamiento utilizado se basa en los siguientes pasos:
    1. Se determina si la celda siguiente, en la dirección actual del movimiento, está libre. Si está libre, se continúa avanzando en esa dirección.
    2. Si la celda situada delante no está libre, se comprueban las distintas direcciones siguiendo un orden de prioridad. Se selecciona una celda libre y se continúa el recorrido desde ella.
    3. Si no existe ninguna celda contigua libre, la posición actual se declara como punto crítico. Esto determina el final de la espiral actual.
    4. Durante el movimiento del robot, las celdas libres situadas alrededor del recorrido se marcan como posibles puntos de retorno.
    5. Cuando se alcanza un punto crítico, se busca un punto de retorno mediante un algoritmo BFS.
  3. Una vez alcanzado el siguiente punto de retorno, se genera una nueva espiral.
  4. El proceso se repite hasta comprobar que el robot ha visitado las celdas navegables del mapa.

Navegación del robot

En este punto del programa ya se dispone de la ruta completa del robot y comienza la fase de navegación.

Para realizar el movimiento se ha implementado un controlador proporcional tanto para la velocidad lineal como para la velocidad angular.

Al robot se le comanda desplazarse hacia el centro de cada celda, utilizando aproximadamente un error de distancia de 0.15.

Además, la velocidad lineal se modifica en función de la distancia restante hasta el centro de la siguiente celda, reduciéndola cuando el robot se encuentra cerca del objetivo para evitar que se pase del centro de la celda.

Resultados y conclusiones

A continuación se adjunta un vídeo acelerado de la ejecución completa del código:

En esta ejecución se puede observar que obtenemos una cobertura del mapa de alrededor del 65%.

Este resultado podría mejorarse afinando el procesamiento del mapa, por ejemplo disminuyendo la erosión aplicada.

La erosión utilizada es relativamente agresiva porque durante las pruebas fue necesario aumentar el margen de seguridad para evitar que el robot se chocase con determinadas esquinas, mesas y otros elementos del entorno.

Sin embargo, esto provoca que determinadas zonas que físicamente podrían ser accesibles por el robot terminen siendo clasificadas como zonas no navegables.

Otro posible punto de mejora está relacionado con la generación de las espirales.

En algunos casos quedan pequeñas zonas libres sin recorrer, lo que posteriormente obliga al robot a realizar desplazamientos relativamente largos para cubrir únicamente unas pocas celdas.

Para mejorar este comportamiento, se podrían tener en cuenta las celdas libres cercanas durante la generación de cada espiral, tratando de evitar dejar pequeños huecos que posteriormente requieran un nuevo punto de retorno.
